# Personal Inbox — журнал решений

Каждая запись — вопрос, который ТЗ раньше оставлял открытым, и его закрытие.
**Это не список тем для обсуждения. Это ответы.** Если вопрос есть здесь —
он решён, переспрашивать не нужно.

Легенда источника: **[В]** — ответ владельца продукта, **[Р]** — вытекает из референса,
**[C]** — принято Claude при составлении ТЗ (можно оспорить, но по умолчанию действует).

---

## Продукт и стек

**1. [В] Что строим.** Полный продукт: фронтенд + бэкенд, реальные подключения,
реальные вызовы модели. Не только дизайн, не только фронт с моками.

**2. [В] Как глубоко инженерить.** Дословно: «не нужно мудрить, это pet-проект,
а не рил продукт в прод». Значит: горутина с тикером вместо брокера очередей,
никаких CI/мониторинга/rate-limiting. При выборе между «правильно по-взрослому»
и «просто и работает» — берём второе. **Уточнено решением №48:** SQLite заменена
на Postgres, добавлен Redis — по прямой просьбе заказчика.

**3. [C] Стек.** React 18 + TypeScript + Vite (фронт), Go + `net/http` + Postgres + Redis (бэк).
Изначально была SQLite без Redis — см. решение №48.
Обоснование: референс написан на React 18, стили переносятся один-в-один.
Бэкенд переписан с Python/FastAPI на Go — см. решение №35.
Tailwind и CSS-in-JS **запрещены** — они ломают точный перенос инлайновых стилей
на CSS-переменных.

**4. [В] Telegram.** Только Bot API. Личный аккаунт через MTProto/Telethon
отклонён: серая зона по ToS Telegram и риск блокировки аккаунта пользователя.
Следствие, которое надо честно показать на экране подключения: бот видит только
чаты, куда его добавили, и не видит личную переписку.

**5. [В] Провайдер модели.** OpenAI, модель по умолчанию `gpt-4o-mini`.
Вызов изолирован в `backend/internal/openai/provider.go` — смена провайдера правит
один файл.

**6. [C] Хранение содержимого.** Полный текст сообщений хранится в БД.
Без него не работают поиск, экран деталей и фоновая переоценка при смене критериев.
Владелец не выбирал этот пункт явно; при желании хранить только метаданные —
поиск и офлайн-лента отпадают, это осознанный размен.

## Функциональность

**7. [C] Восстановление пароля.** В MVP нет. Ссылки «Забыли пароль?» на экране входа
нет. Причина: нужен почтовый отправитель, для pet-проекта с одним пользователем избыточно.
Смена пароля при известном старом — есть, она в настройках.

**8. [C] Подтверждение email при регистрации.** Нет, по той же причине.

**9. [Р] Периоды сводки.** `24ч` · `Неделя` · `Месяц`.
Здесь было **прямое противоречие**: референс давал третьим сегментом `Период`
с подписью «Произвольный диапазон», а обе спецификации говорили, что календаря в MVP нет.
Победило «календаря нет» — третий сегмент переименован в `Месяц`.
Это единственное место, где мы сознательно отступаем от референса.

**10. [C] Фильтр «Период» в ленте.** Обязан работать: `Всё время` / `Сегодня` /
`Неделя` / `Месяц`, по `received_at`. В референсе фильтр объявлен, но в функции
сопоставления не применён — это баг прототипа, а не задумка.

**11. [Р] Что значит статус «Обработано».** Сообщение прошло оценку моделью
(`status = DONE`). Это **не** действие пользователя: кнопки «пометить обработанным»
в интерфейсе нет и не будет.

**12. [Р] Пометить прочитанным.** Автоматически при открытии деталей.
Обратной операции «пометить непрочитанным» в MVP нет.

**13. [C] Категория и срок.** Свободные строки от модели, справочника нет.
Следствия: фильтра по категории нет; `deadline_text` не сортируется и не сравнивается,
только показывается; пустое значение = чип не рендерится.

**14. [C] Что делать, если модель не ответила.** Три повтора (2с / 8с / 30с),
затем `status = DONE`, `level = NORMAL`, пометка «Оценка недоступна» на карточке.
Сообщение **никогда** не пропадает из ленты из-за ошибки модели.

**15. [C] Ручное исправление при переоценке.** `level_override` не затирается
фоновой переоценкой. Если пользователь поставил уровень руками — показывается он.

**16. [C] Глубина импорта при первом подключении.** Gmail: 30 дней, максимум 200 писем.
Telegram: только сообщения, пришедшие после добавления бота — Bot API не отдаёт историю.

**17. [C] Частота синхронизации.** Раз в 5 минут (горутина с `time.Ticker`).
Gmail — инкрементально по `historyId`, Telegram — long polling `getUpdates`.

**18. [C] Доставка новых сообщений на фронт.** Server-Sent Events (`/api/stream`),
откат на опрос раз в 30 секунд. WebSocket не нужен — поток односторонний.

**19. [C] Вложения и треды.** Вложения — только имя файла, скачивания нет.
Тред писем — одно письмо = одна карточка, склейки в переписку нет.

## Интерфейс

**20. [В+Р] Носители.** Один адаптивный интерфейс, граница `900px`.
Не два отдельных дизайна.

**21. [Р] Структура ленты.** Два уровня: разделы источников → сообщения внутри источника.
Сквозной вкладки «Все источники» нет. Фильтра по источнику на уровне 2 нет —
источник уже задан разделом.

**22. [Р] Отключённые источники в ленте.** Не показываются вообще.
Их место — экран «Источники».

**23. [Р] Источники из планов развития.** GitHub, Slack, Notion показываются
в выборе сервиса неактивными, с пометкой «Скоро». Показываем, а не скрываем.

**24. [Р] Как открывается сообщение.** Лист снизу на телефоне, панель справа
на десктопе. Фон притемняется и размывается.

**25. [Р] Где меняется уровень важности.** Только в деталях сообщения.
На карточке в ленте — нельзя.

**26. [Р] Новые сообщения.** Автовставка сверху с синей подсветкой.
Промежуточной плашки «Показать новые» нет.

**27. [C] Язык.** Только русский, i18n-библиотека не подключается,
строки пишутся прямо в коде.

**28. [C] Где живут переключатели темы и плотности.** В настройках, раздел
«Внешний вид». В прототипе они были вынесены над макетом — это инструмент
демонстрации, а не часть продукта. Выбор сохраняется в `localStorage`
и применяется до первого рендера.

**29. [Р] Дизайн-система Broadsheet.** Не используется. Запрос был на Liquid Glass,
и это прямое противоречие двух направлений. Выбран Liquid Glass.

## Принято при реализации бэкенда

**30. [C] Библиотека для Telegram.** Обращаемся к Bot API напрямую через
`net/http`, без клиентских библиотек. Нужны ровно три метода — `getMe`,
`getUpdates`, `getChatMemberCount`, — ради них тащить фреймворк незачем.
То же решение принято для Gmail и OpenAI: обычные HTTP-запросы вместо SDK.

**31. [C] Часовой пояс в фильтре «Период».** Вариант `Сегодня` считается от местной
полуночи, поэтому фронт передаёт `tz_offset` в минутах. Сервер хранит время в UTC
и не угадывает зону пользователя.

**32. [C] Схема БД и миграции.** Отдельного инструмента миграций нет: файлы
`.sql` лежат в `backend/internal/postgres/migrations`, встроены в бинарник через
`embed` и накатываются по порядку при открытии базы, применённые версии
записываются в `schema_migrations`. Свежая копия проекта поэтому поднимается
одной командой — отдельного шага или сервиса миграции нет ни в Makefile,
ни в docker compose.

**33. [C] Переоценка при смене критериев.** Идёт одной фоновой горутиной,
сообщения обрабатываются по очереди. ТЗ говорит «партиями по 10»; при одном
рабочем потоке это то же самое, только без лишнего кода.

**34. [C] Пометка «Оценка недоступна».** Хранится отдельным полем
`message.analysis_failed`. Отличить «модель вернула NORMAL» от «модель не ответила»
иначе невозможно, а на карточке это разные состояния.

**35. [C] Ссылка «Открыть в Telegram».** Есть только у чатов с `@username`;
у групп без публичного имени прямой ссылки не существует, поэтому `external_url`
остаётся пустым, и кнопка не рендерится.

**36. [C] Демо-данные.** Заливаются командой `make seed` на пользователя
`demo@personal.inbox` / `demo12345`. Очередь живой демонстрации (3 сообщения)
проигрывается флагом `DEMO_LIVE=1` при старте сервера — события SSE живут
в памяти процесса, из отдельного скрипта их не отправить.

**37. [C] Медиа без подписи.** Сообщения Telegram без текста пропускаются:
оценивать нечего, а пустая карточка в ленте бесполезна. Курсор `update_id`
при этом сдвигается.

**38. [C] Неудачная переоценка не стирает прежнюю оценку.** Правило «после трёх
неудач NORMAL и пустые поля» из п. 6.1 применяется только к сообщению, которое
ещё ни разу не оценивалось. Если карточка уже была заполнена, при неудачной
переоценке остаются прежние значения плюс пометка «Оценка недоступна»:
потерять готовую карточку хуже, чем показать чуть устаревшую.

## Принято при реализации фронтенда

**39. [C] Где хранится тема и плотность.** Источник правды — профиль на сервере;
`localStorage` держит копию и применяется до первого рендера, чтобы не было вспышки
чужой темы. При входе значения из профиля перекрывают локальные.

**40. [C] Новое сообщение при активных фильтрах.** Если в ленте включены фильтры
или поиск, пришедшее по SSE сообщение не вставляется вслепую: список перезапрашивается
у бэкенда. Иначе в выборке появлялись бы карточки, не подходящие под фильтр.

**41. [C] Лист деталей и модальные окна рендерятся в `body`.** Иначе притемнение
фона накрывает не всё окно, а только колонку с лентой.

**42. [C] Поиск отправляется с задержкой 250 мс.** Запрос на каждую букву нагружает
бэкенд без пользы; на глаз задержка незаметна.

## Как добавлять сюда записи

Если при работе возник вопрос, ответа на который нет ни здесь, ни в остальных
`docs/`, ни в референсе — **выбрать самый простой вариант, реализовать его
и дописать сюда запись с пометкой [C]**. Останавливаться и спрашивать —
только если варианта два и они несовместимы по схеме данных.

**35. [C] Бэкенд на Go.** Бэкенд переписан с Python/FastAPI на Go 1.24 по прямому
требованию владельца. Что изменилось и почему именно так:

- **Веб-фреймворка нет.** С Go 1.22 маршрутизатор стандартной библиотеки понимает
  метод и параметры пути (`GET /api/messages/{id}`) — этого хватает на 16 ручек.
- **ORM нет.** Четыре таблицы и полтора десятка запросов; обычный SQL в
  `internal/postgres` читается лучше, чем слой поверх него.
- **Драйвер БД — чистый Go** (тогда `modernc.org/sqlite`, теперь `pgx`). Собирается
  без cgo, бинарник переносится как файл. В SQLite встроенный `lower()` умел только
  латиницу, поэтому под русский поиск заводилась своя функция `unilower`; в Postgres
  `lower()` понимает Unicode сам, и костыль убран (решение №48).
- **Зависимостей было две:** драйвер БД и `bcrypt` (после решения №48 добавился
  `go-redis`). Версии подобраны так, чтобы
  проект собирался локальным Go 1.24 без докачивания тулчейна.
- **Сессия** — своя подписанная cookie (HMAC-SHA256 на `SESSION_SECRET`) вместо
  `SessionMiddleware` из Starlette. Формат cookie сменился, поэтому после
  переезда все выданные ранее сессии недействительны.
- **Контракт API не изменился ни в одном поле:** те же пути, те же коды ответов,
  тот же формат ошибок `{"detail": ...}` и то же время в ISO без зоны. Фронтенд
  не правился совсем; форматы закреплены тестами
  (`TestMessageTimeFormatMatchesFrontend`).
- **Тесты перенесены на `go test`** и покрывают то же, что покрывал `pytest`:
  фильтры и периоды, повторы вызова модели, оба источника через поддельные
  HTTP-серверы, ручки, SSE и демо-данные.
- **Демо-данные из референса перенесены дословно** и сверены с прежней версией
  посимвольно.

**43. [C] docker compose — штатный способ запуска.** Запрет на Docker снят из
границ MVP (docs/00, п. 2 и 8): `docker compose up --build` поднимает весь стек
одной командой, `make run`/`make front` остаются для разработки без контейнеров.

Ровно два сервиса, оба нужны приложению:

- `backend` — multi-stage сборка Go, статический бинарник на alpine, наружу порт
  не выставляется (после решения №48 рядом появились `postgres` и `redis`);
- `nginx` — собранная статика Vite плюс прокси `/api` на `backend:8000`. Фронт и
  API на одном origin, поэтому сессионная cookie ходит как своя и CORS не нужен.
  Для `/api/stream` буферизация и таймаут чтения сняты, иначе SSE не доходит.

Сервисов миграции и тестов нет и не будет: схема накатывается при старте сервера,
тесты гоняются руками. Демо-данные — разовая команда `docker compose exec backend
/app/seed` в уже поднятом стеке.

**44. [C] Сверка фронтенда с референсом.** Реализация прогнана по
`docs/reference/reference-source.html` экран за экраном (телефон и десктоп,
обе темы) и приведена к нему. Что разошлось и исправлено:

- **Сводка, Источники, Настройки — одна прокручиваемая колонка.** В референсе
  заголовок лежит внутри скролла, а не в закреплённой шапке. Ширина колонки:
  сводка — 820px, источники и настройки — 720px (было 820px у всех трёх и
  шапка во всю ширину, из-за чего переключатель периода уезжал к краю окна).
- **Две карточки «требуют ответа» и «требуют действия» — в ряд и на телефоне**
  (`grid-template-columns: 1fr 1fr`); было схлопывание в столбец до 900px.
- **Кнопка «Фильтры» не переносится под заголовок ленты.** Перенос
  (`flex-wrap`) в референсе есть только в шапке сводки — вынесен в модификатор.
- **Уровень важности: линза и активная подпись красятся в цвет уровня.**
  Было нейтральное стекло — уровень отличался только положением линзы.
- **Шапка деталей — метка источника** (36px, буква сервиса, градиент сервиса),
  а не аватар отправителя с бейджем.
- **Карточка подключения:** метка 38px/13px вместо 44px/15px, скругление 24px,
  строка состояния в одну строку с многоточием и цветом `--ink2`.
- **«Выйти из аккаунта»** набрано цветом уровня «критично».
- **Кнопка входа** крупнее общей первичной: `16px 22px`, `600 15.5px/1`;
  ссылка «Нет аккаунта? Зарегистрироваться» — по центру, `--ink2`, а не синяя.
- **Отступ шапки на телефоне** `8px 18px 12px` — как `padHead` в референсе.
- **Ссылки без подчёркивания** (`a { text-decoration: none }`).
- **Счётчики убраны из таб-бара телефона:** в референсе бейджи рисует только
  боковая панель десктопа.

Сознательно оставлены расхождения, закреплённые в ТЗ:

- третий период сводки — `Месяц`, а не `Период` (решение №9: календаря нет);
- блок «Внешний вид» в настройках (`docs/02-screens.md`, п. 8.3): в референсе
  тема и плотность живут в обвязке прототипа, а не внутри приложения;
- подпись пользователя в боковой панели — email и «Аккаунт»: имени
  пользователя в модели данных нет.

**45. [C] Референс открывается без сети.** `docs/reference/Personal Inbox.dc.html`
самодостаточен: рантайм и React лежат внутри файла, внешних запросов нет —
проверено в Chromium с заблокированной сетью. `reference-source.html` — тот же
документ, распакованный для чтения; сам по себе он не отрисовывается, потому
что ссылается на рантайм из бандла. Открывать — `.dc.html`, читать —
`reference-source.html`.

**46. [C] Раскладка бэкенда: папка на сервис.** По прямой просьбе структура
приведена к виду «каждый внешний сервис — своя папка, внутри классы для работы
с ним». Стек тогда не менялся: тот же Go, та же SQLite (её заменил Postgres
позже — решение №48).

```
backend/internal/
  core/         настройки: окружение, .env, константы
  routers/      маршруты и ручки, session.go — подписанная cookie
  schemas/      схемы ответов API
  exceptions/   сквозные ошибки: не найдено, модель недоступна, сбой источника
  services/     бизнес-логика: analysis · ingest · scheduler · seed
  sqlite/       база: модели, SQL, миграции, фильтры ленты (теперь postgres/)
  openai/       адаптер модели
  gmail/        OAuth + History API
  telegram/     Bot API
  events/       шина событий для SSE
  utils/        security — пароли (bcrypt)
```

Было: `config`, `api`, `view`, `store`, `llm`, `sources/{gmail,telegram}` и
`analysis`/`ingest`/`scheduler`/`seed`/`security` вперемешку в корне `internal`.
Переименование чисто механическое: публичные типы и поведение не тронуты,
`go build`, `go vet` и `go test ./...` зелёные, ручной прогон сценария
вход → лента → источник → детали → исправление уровня → сводка прошёл без ошибок.

Новое здесь только `exceptions`: четыре сквозные ошибки (`ErrNotFound`,
`ErrModelUnavailable`, `ErrGmail`, `ErrTelegram`) лежали каждая в своём пакете,
из-за чего ручка ради «не найдено» импортировала слой БД. Теперь они в одном
месте и проверяются через `errors.Is` без лишних связей.

**Чего в раскладке нет: Kafka, MongoDB, S3, ClamAV.** Их запрещает ТЗ
(`docs/00-product-spec.md`, п. 1) и ничто в продукте их не требует. Redis из
этого списка позже вычеркнут — см. решение №48: он появился вместе с Postgres
по прямой просьбе заказчика.

**47. [C] `index.html` нельзя открыть с диска.** Это SPA: собранная страница
подключает JS как ES-модуль, а браузер запрещает модули по `file://` (CORS,
origin `null`), поэтому остаётся пустой `<div id="root">` и 404 в консоли.
Лечится не правкой файла, а http-сервером: `docker compose up --build` →
`http://localhost:8080`. Заодно в Vite выставлен `base: './'` — пути к ассетам
стали относительными, и сборка больше не привязана к корню сайта.
Предупреждение об этом добавлено в README.

**48. [В] Postgres и Redis вместо SQLite.** Прямое требование заказчика:
«добавить Postgres и Redis по-настоящему». Прежний ответ — «ТЗ запрещает
Redis» — снят: ТЗ поправлено под новое решение, а не наоборот.

**Postgres 16 вместо SQLite** (`internal/postgres`, драйвер `pgx` — по-прежнему
чистый Go, сборка без cgo):

- время лежит в `timestamptz`, а не строкой: пропали `ToDBTime`/`FromDBTime`
  и разбор пяти форматов при чтении;
- `boolean` вместо `0/1`, `BIGSERIAL` вместо `INTEGER AUTOINCREMENT`;
- регистронезависимый поиск — встроенным `lower()`, своя функция `unilower`
  больше не нужна;
- таблица `user` переименована в `users`: `user` — зарезервированное слово;
- `LastInsertId` в Postgres нет, вставки возвращают id через `RETURNING`;
- запросы в пакете по-прежнему пишутся с `?`, а `rebind` переводит их в `$N`
  перед отправкой: так условие можно вставить в середину, не перенумеровывая
  всё следом. Внутри строковых литералов замена не делается.

**Redis 7** (`internal/redis`) — с двумя настоящими задачами, а не «для галочки»:

- **сессии.** Раньше это была подписанная cookie: выход гасил её только
  в браузере, украденная кука жила до истечения срока. Теперь в cookie лежит
  непрозрачный случайный токен, всё остальное — на сервере, и `logout`
  удаляет ключ. На это есть тест `TestLogoutKillsSessionOnServer`;
- **кэш** сводки и счётчиков источников на 45 секунд — два самых дорогих
  запроса, фронт дёргает их при каждом переключении вкладки. Инвалидация
  повешена на шину событий (`events.Bus.OnPublish`): через неё проходит любое
  изменение ленты, поэтому сбрасывать кэш вручную в каждом месте записи не
  нужно. Отметка о прочтении, смена подключений и переоценка событий не
  публикуют — там сброс явный.

Очередь оценки осталась в памяти: выносить её в Redis — это уже распределённая
очередь со своими сбоями, а выигрыша на одном процессе нет.

**Тесты ходят в настоящие Postgres и Redis**, без моков и без in-memory подмен:
каждый тест получает свою схему в базе и свой префикс ключей и убирает их
за собой (`internal/testenv`). Если сервисы не подняты, тесты падают, а не
пропускаются молча — молча пропущенный тест хуже упавшего.

**В compose теперь четыре сервиса:** `postgres` (том `pgdata`), `redis`
(`appendonly`, том `redisdata` — иначе перезапуск разлогинивал бы всех),
`backend` и `nginx`. Бэкенд стартует только после healthcheck базы и Redis.
