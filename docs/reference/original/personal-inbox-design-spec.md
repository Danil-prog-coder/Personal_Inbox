# Personal Inbox — спецификация для дизайнера

Документ описывает экраны, состояния и сценарии, которые должны быть учтены в дизайне. Обновлён по референс-прототипу (Liquid Glass, `Personal Inbox.dc.html`) — там, где прототип уже даёт ответ на вопрос из ТЗ, документ зафиксирован по прототипу. Расхождения с более ранней версией спецификации отмечены отдельно в разделе 11.

Визуальный стиль (конкретные цвета, шрифты, толщина размытия и т.д.) документ не переопределяет — он уже задан референс-прототипом и описан в `personal-inbox-описание.md`. Здесь фиксируется состав экранов, состояния и функциональная логика.

**Носители и темы:** дизайн должен покрывать два носителя (iPhone и десктоп) и две темы (тёмная и светлая) на едином наборе правил — это не два отдельных дизайна, а один, адаптированный под ширину экрана.

---

## 1. Онбординг

### 1.1 Регистрация / вход
- Экран регистрации: email + пароль
- Экран входа: email + пароль
- Переключение между входом и регистрацией — одной ссылкой на этом же экране, без перехода на отдельную страницу

### 1.2 Задание критериев важности (первый запуск)
- Одно большое текстовое поле с содержательным примером в placeholder
- Пояснение рядом с полем: это не жёсткие правила, а контекст для модели
- Шаг можно пропустить и задать/изменить критерии позже в настройках

---

## 2. Подключение источников

### 2.1 Экран "Источники" — три состояния подключения
- **Не подключён** — кнопка "Подключить"
- **Активно** — отображается аккаунт и время последней синхронизации, кнопка отключения
- **Требуется повторная авторизация (REAUTH_REQUIRED)** — визуально выделенное предупреждение (акцентная рамка), поясняющий текст, что ранее полученные сообщения остаются в ленте. Подключение и отключение источника подтверждаются отдельной плашкой

### 2.2 "Добавить источник"
- Открывает экран выбора сервиса
- Доступны для подключения: Gmail, Telegram
- Технически ещё не реализованные источники (GitHub, Slack, Notion) показываются в этом списке как неактивные, с пометкой "Скоро" — это решённый вопрос: roadmap-источники показываются, а не скрываются

### 2.3 Процесс подключения Gmail (OAuth)
- Нажатие "Подключить" → переход на страницу авторизации Google (внешний экран, не часть дизайна продукта)
- Возврат в приложение → подтверждение успешного подключения (плашка)
- Состояние ошибки: пользователь отменил авторизацию / Google вернул ошибку

### 2.4 Процесс подключения Telegram
- Отдельный флоу, детали зависят от выбранного технического механизма (bot API или user-авторизация) — уточняется отдельно на техническом уровне
- Нужен экран инструкции для пользователя, если требуется дополнительное действие

## 3. Главный экран: два уровня ленты

Лента строится в два уровня: сначала разделы источников, затем — по тапу — сообщения внутри выбранного источника. Отдельного фильтра или вкладки "по источнику" на уровне сообщений нет — источник уже зафиксирован разделом, в который зашёл пользователь. Общей сквозной вкладки "Все" (все источники сразу) в структуре нет.

### 3.1 Уровень 1 — разделы источников
Раздел показывается только для **подключённых** источников. Отключённые/не подключённые источники в ленте не отображаются (их место — экран "Источники", раздел 2).

Карточка раздела-источника содержит:
- Аватар/логотип сервиса
- Аккаунт (например, адрес почты или имя в Telegram)
- Общее число сообщений
- Счётчик непрочитанных
- Полосу распределения сообщений по уровням важности
- Самое срочное сообщение раздела — одной строкой
- Если токен истёк — предупреждение прямо на карточке раздела (см. REAUTH_REQUIRED, п. 2.1)

### 3.2 Переход на уровень 2
Тап по карточке раздела открывает список сообщений этого источника:
- Кнопка "назад" к разделам
- Название сервиса в заголовке
- Поиск и фильтры (раздел 5) — действуют уже внутри выбранного источника

### 3.3 Карточка сообщения (уровень 2)
- Аватар с инициалами отправителя + бейдж источника
- Имя отправителя, адрес, время
- Тема — крупным кеглем
- Сниппет содержимого — до трёх строк
- Метаданные: уровень важности, категория, срок
- Компактные значки "требует действия" / "требует ответа"
- Непрочитанное сообщение — тема жирнее + синяя точка-индикатор

### 3.4 Появление новых сообщений (реальное время)
Зафиксировано по прототипу — без промежуточной плашки "Показать новые":
- Новая карточка появляется сверху списка сама, с синей подсветкой
- Сразу видны отправитель и тема
- На месте блока оценки — индикатор "Определяем важность…" (сообщение уже в статусе PROCESSING)
- Через некоторое время карточка "дозаполняется" — появляются уровень важности, категория, срок, подсветка гаснет

### 3.5 Прочие состояния уровня 2
- Пустая лента при первом использовании источника (сообщений ещё нет)
- Пустая лента после фильтрации (ничего не найдено по заданным фильтрам) — с возможностью сбросить фильтры

## 4. Детали сообщения и исправление оценки

Открывается по тапу на карточку сообщения: на телефоне — стеклянный лист снизу почти на весь экран, на десктопе — панель справа; фон позади притемняется и размывается.

Содержимое:
- Отправитель, тема
- Краткое содержание (summary), сформированное моделью — выделено визуально отдельным блоком (акцентная рамка), чтобы не путать с оригинальным текстом
- Метаданные: уровень важности, категория, срок
- Полный текст сообщения
- Кнопка перехода в исходный сервис ("Открыть в Gmail" / "Открыть в Telegram")
- Переключатель уровня важности (ручное исправление оценки) — с подтверждением "Сохранено" после изменения

Именно здесь, а не на самой карточке в ленте, находится единственная точка ручного исправления результата анализа.

## 5. Фильтрация и поиск

Действуют внутри выбранного источника (уровень 2 ленты).

### 5.1 Фильтры
- По уровню важности (CRITICAL / HIGH / NORMAL / LOW / все)
- По статусу: не прочитано / прочитано / обработано
- По необходимости ответа (да / нет)
- По необходимости действия (да / нет)
- По периоду — предустановленные варианты (например, сегодня / неделя / месяц). Фильтра по произвольному диапазону дат (календарь) на MVP нет — решение зафиксировано референсом

Активный фильтр помечается визуальным акцентом (точка-индикатор). Есть сброс всех фильтров одним действием.

### 5.2 Поиск
- Поле поиска по тексту сообщений внутри источника

## 6. Сводка (Summary)

- Число новых сообщений за период — крупно
- Распределение по уровням важности — полосой с легендой
- Два показателя: "требуют ответа" и "требуют действия"
- Список главных событий за период, с переходом по клику к соответствующему сообщению в ленте
- Переключатель периода — сегментированный контрол (предустановленные периоды, без произвольного диапазона)
- Формируется асинхронно: при смене периода — состояние ожидания "Сводка формируется" (порядка 10–20 секунд)

---

## 7. Настройки

### 7.1 Критерии важности
- Редактирование текста критериев (тот же ввод, что при онбординге)
- Предупреждение при сохранении: изменение критериев запускает фоновую переоценку существующих сообщений, не мгновенно

### 7.2 Подключения
- Ссылается на экран "Источники" (раздел 2) либо дублирует его

### 7.3 Аккаунт
- Смена пароля, выход из аккаунта (выход возвращает на экран входа)

---

## 8. Общий паттерн взаимодействия

Один визуальный приём (перемещение выделения к активному элементу) используется в четырёх местах интерфейса — стоит закладывать его как переиспользуемый компонент, а не четыре разных:
- Таб-бар на телефоне
- Боковая навигация на десктопе
- Переключатель периода в сводке
- Переключатель уровня важности в деталях сообщения

---

## 9. Не входит в MVP (не проектировать)

- Полноценный интерфейс переписки внутри Personal Inbox (ответ на сообщение прямо из приложения) — только переход в оригинальный сервис
- Реальные подключения и полноценная авторизация к внешним сервисам в самом дизайне — это уже вопрос технической реализации, не экранов
- Отправка уведомлений на устройство
- Поддержка источников, кроме Gmail и Telegram
- Настройка пользователем собственных уровней важности (уровни фиксированы: 4 штуки)
- Фильтр по произвольному диапазону дат (календарь)
- История изменений/редактирования сообщений
- Пагинация при больших объёмах данных и состояния ошибок сети
- Multi-workspace / командные функции — проект строится как персональный инструмент одного пользователя

## 10. Данные для наполнения макетов (ориентир)

Для содержательных, а не "лорем-ипсум" макетов стоит опираться на разнородный набор примеров, как в прототипе:
- Gmail: договор с дедлайном на сегодня, налоговое уведомление, платёж, оффер кандидату, перерасход бюджета, макеты на ревью, банковская выписка, дайджест, продление подписки, коммерческое предложение, уведомление о входе
- Telegram: вопросы по юнит-экономике, релизный блокер, алерт дежурства, закрывающие документы, дизайн-ревью, личные сообщения, сервисный бот

Разнородность важна, чтобы дизайн проверялся на реалистичных крайних случаях (очень длинная тема письма, сообщение без срока, критичное сообщение без необходимости ответа и т.д.), а не только на аккуратных тестовых данных.
